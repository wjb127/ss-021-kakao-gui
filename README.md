# Kakao Inbox

카카오톡 로컬 데이터를 읽어 고객 대화와 첨부파일을 관리하는 macOS 인박스다.

## 팀 계정

한 대의 맥에 연결된 카카오톡 인박스를 관리자 포함 최대 10개의 활성 계정으로 사용한다.
다른 사람의 카카오톡 계정을 추가로 연결하는 기능은 아니다. 서버 맥과 카카오톡이 실행 중이어야 한다.

- 관리자: 모든 채팅방 조회와 기존 관리·발송 기능, 팀 계정 관리.
- 열람자: 관리자가 선택한 채팅방의 메시지·메모·분석·요청·첨부 조회와 검색·복사.
- 새 열람자는 기본적으로 어떤 채팅방도 볼 수 없다. 초대 대기 계정도 활성 인원에 포함한다.
- 계정 비활성화·비밀번호 재설정·접속 종료는 기존 세션을 회수한다. 조회 권한 변경은 다음 API 요청부터 적용하며, 열린 화면의 캐시는 15초 이내 또는 창 재활성화 때 비운다.
- 이미 복사하거나 내려받은 내용까지 회수하지는 않는다.

최초 관리자 생성은 서버 맥에서 한 번 실행한다.

```bash
pnpm team:setup
```

기본 아이디는 `admin`이다. 다른 아이디는 `pnpm team:setup owner`처럼 전달한다.
출력된 로컬 초대 코드 파일을 열어 로그인 화면의 **초대 코드로 계정 시작**에서 비밀번호를 설정한다.
초대 코드는 24시간 동안 한 번만 유효하고, 파일은 소유자만 읽을 수 있다. 서버에 이미 계정이 있으면 최초 생성은 거부된다.
로그인 후 **팀 관리**에서 팀원을 생성하고 조회할 채팅방을 선택해 저장한다.
비밀번호 재설정 코드를 발급하면 이전 비밀번호와 기존 접속이 해제된다.
최초 코드가 만료되거나 유일한 관리자의 비밀번호를 잊은 경우 서버 맥에서 `pnpm team:recover`를 실행해 새 코드를 발급한다.
다른 관리자 아이디는 `pnpm team:recover owner`처럼 지정한다. 이 명령도 기존 비밀번호와 접속을 해제한다.

팀원 접속은 접근을 허용한 사내망/VPN과 HTTPS를 사용한다. 프록시를 사용할 경우 원래 `Host`를 유지해야 한다.
IP 허용 목록과 여러 카카오톡 계정 연결은 이 버전에 포함하지 않는다.
열람자의 ‘파일 저장’은 자기 기기로 파일을 내려받는다. 관리자에게 기존처럼 제공되는 ‘열기/폴더’는 서버 맥에서 실행된다.
여러 관리자가 동시에 발송하면 공용 카카오톡 화면 충돌을 막기 위해 진행 중인 발송 외 요청은 재시도 안내로 거절한다.

계정·세션·조회 권한은 기존 SQLite의 `team_*` 테이블에 저장한다. 비밀번호는 scrypt 해시, 세션·초대 코드는 SHA-256 해시만 저장한다.
`KAKAOGUI_DATA_DIR`로 인박스 DB 디렉터리를 별도로 지정할 수 있다. 기존 기본 경로는 `~/.kakaocli` 그대로다.

```bash
pnpm test:team
```

위 검증은 임시 DB에서 실행하며 실제 카카오톡 데이터·외부 메시지 발송을 사용하지 않는다.
브라우저 검증용 합성 데이터는 `pnpm exec tsx scripts/team-qa-fixture.ts`로 만들 수 있다.
출력된 경로를 `KAKAOGUI_DATA_DIR`로 지정하고, `KAKAOGUI_DISABLE_WORKER=1 KAKAOCLI_DB='' KAKAOCLI_KEY=''` 환경으로 3043 포트 서버를 시작한다.
같은 경로를 지정한 `pnpm exec tsx scripts/test-team-http.ts`는 격리 서버에서 10개 계정의 실제 HTTP 로그인과 조회를 검증한다.

## macOS 앱 설치

크롬과 독립된 `WKWebView` 앱과 production 서버를 함께 설치한다.

```bash
pnpm local:install
```

설치 후 앱은 `~/Applications/Kakao Inbox.app`에 생성된다. 앱을 열면 로컬 서버 상태를 확인하고, 서버가 꺼져 있으면 launchd 서비스를 복구한 뒤 인박스를 연다.

코드를 수정한 뒤에는 `pnpm local:install`을 다시 실행해 production 빌드를 갱신한다. 단순 재실행은 다음 명령을 사용한다.

```bash
pnpm local:restart
```

개발 서버는 다음 명령으로 실행한다.

```bash
pnpm dev
```

설치된 앱 서버는 `http://localhost:3032`, 개발 서버는 `http://localhost:3033`을 사용한다.

## 대화 로딩

목록은 SQLite에 저장한 최근 목록부터 표시하고 원본 목록을 백그라운드에서 갱신한다.
캐시 가능한 소규모 채팅방(10명 이하)은 저장된 최신 300건을 먼저 표시한 뒤 최근 3일을 동기화한다.
처음 여는 방은 최신 응답 이후 기존 범위인 최대 50일·5,000건을 한 방씩 보충한다.
이미 저장된 과거 대화는 삭제하지 않으며, 위쪽 600px 이내로 스크롤하면 300건씩 추가 조회한다.
과거 페이지는 카카오 원본 조회 없이 SQLite 커서로 읽고 읽던 위치를 유지한다.

로딩 경로 회귀 검증: `node --experimental-strip-types scripts/test-inbox-loading.ts`
